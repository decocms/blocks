# Next.js App Router

In this guide, you'll render CMS pages with Server Components, stream each of a page's blocks under its own Suspense boundary, and generate metadata from the page's SEO block.

Each of a page's [blocks](/next/model#resolving-a-page-step-by-step) resolves on its own, so a slow block never holds up the rest. Editors also choose page URLs in Studio, so your app can't know its routes ahead of time. Instead, one catch-all route receives every URL, asks `matchRoute` which page or redirect owns it, and renders that page's blocks.

**Prerequisites:** an App Router app (the SDK reads no files, so the Node and Edge runtimes both work), with a root layout; `npm install @decocms/blocks server-only` and the CLI from [Quickstart](/next/quickstart); and the [example project](/next/routing#the-example-used-here-and-in-the-guides): `src/model.ts` plus the entries in `.deco/blocks` at the project root.

## 1. Add the components

`PromoBanner` and `ProductHero` are the components the two blocks render. `CartButton` is a Client Component with state, there to show that interactive components keep working inside blocks the CMS renders on the server. None of them knows about the CMS.

```tsx title="src/CartButton.tsx"
"use client";
import { useState } from "react";

export default function CartButton() {
  const [count, setCount] = useState(0);
  return (
    <button type="button" onClick={() => setCount((value) => value + 1)}>
      Add to cart ({count})
    </button>
  );
}
```

```tsx title="src/PromoBanner.tsx"
import type { PromoBannerProps } from "./model";

export default function PromoBanner({ title, href }: PromoBannerProps) {
  return (
    <a href={href} role="note">
      {title}
    </a>
  );
}
```

```tsx title="src/ProductHero.tsx"
import CartButton from "./CartButton";
import type { ProductHeroProps } from "./model";

export default function ProductHero({ name, price, currency, image }: ProductHeroProps) {
  const formatted = new Intl.NumberFormat("en-US", { style: "currency", currency }).format(price);
  return (
    <section>
      <img src={image} alt={name} />
      <h1>{name}</h1>
      <p>{formatted}</p>
      <CartButton />
    </section>
  );
}
```

## 2. Create the CMS

Both blocks return JSX. Next renders them as Server Components, and `CartButton` stays a Client Component.

```tsx title="src/blocks.tsx"
import type { Blocks } from "@decocms/blocks";
import ProductHero from "./ProductHero";
import PromoBanner from "./PromoBanner";
import type { ProductHeroProps, PromoBannerProps, SEO, StoredPage } from "./model";

export type Content = { page: StoredPage };

export default {
  seo: (input: SEO) => input,
  "promo-banner": (input: PromoBannerProps) => <PromoBanner {...input} />,
  "product-hero": (input: ProductHeroProps) => <ProductHero {...input} />,
} satisfies Blocks;
```

`seo` returns its input. Registering it lets editors save SEO as a reusable entry with its own form. `page` and `redirect` are [built-in blocks](/next/model#the-rule): the framework adds them to this map, so they aren't listed here. The `Content` export overrides the page *schema* with the narrower `StoredPage` from [the example](/next/routing#the-example-used-here-and-in-the-guides), so Studio only saves pages this guide's code can read.

`cms.ts` imports the [content module](/next/content#the-content-module), `.deco/blocks.gen.ts`: the file the CLI command `deco content` generates from your JSON files, exporting a snapshot `{ revision, blocks }` (one fixed copy of all your saved entries). Step 3 sets up that command; until it has run once, TypeScript can't find the import.

```ts title="src/cms.ts"
import { createCMS } from "@decocms/blocks";
import content from "../.deco/blocks.gen";
import blocks from "./blocks";

// Development (no site or token) reads the content module. Production reads releases from the
// Deco API and falls back to it.
export const cms = createCMS({ blocks, content, site: process.env.DECO_SITE, token: process.env.DECO_SITE_TOKEN });
```

The content options and their fallbacks are in [Configuring content](/next/content#configuring-content). Upstream caching and inbound-request telemetry come from the [framework binding](/next/architecture#key-terms), which this guide doesn't use yet; see the [Roadmap](/roadmap#roadmap-api--cache-upstream-requests-in-the-bindings).

```ts title="src/client.server.ts"
import "server-only";
import { cookies } from "next/headers";
import { DRAFT_COOKIE } from "@decocms/blocks";
import { cms } from "./cms";

// The client for this request: a draft when the cookie holds a valid pointer, production otherwise.
// In development (no site or token), drafts and releases read the same content.
export async function client() {
  const pointer = (await cookies()).get(DRAFT_COOKIE)?.value;
  return pointer ? cms.forDraft(pointer) : cms.forRelease();
}
```

`import "server-only"` makes the build fail if a Client Component imports this file, which keeps the token and the CMS out of the browser.

## 3. Generate the schema and content

Two CLI commands generate the files the app and Studio need (see [CLI reference](/next/schema#the-two-cli-commands)): `deco schema` writes `.deco/schema.json`, a form for each block type in Studio, from the block map it finds in `src/blocks.tsx`, and `deco content` writes the content module `cms.ts` imports. Run both before the dev server and the build:

```json title="package.json"
{
  "scripts": {
    "predev": "deco schema && deco content",
    "prebuild": "deco schema && deco content"
  }
}
```

Commit `.deco/schema.json` and gitignore `.deco/blocks.gen.ts`. What reloads on its own is in [The content module](/next/content#the-content-module); while you work, you can leave `deco content --watch` running beside `next dev`.

## 4. Keep preview working across pages

Studio opens your site with the [draft pointer](/next/preview) in the URL. `proxy.ts` (called `middleware.ts` before Next.js 16) runs before every request and turns that pointer into a cookie, so the editor stays in preview while clicking around. `client()` reads the cookie.

```ts title="src/proxy.ts"
import { NextResponse, type NextRequest } from "next/server";
import { draftCookie } from "@decocms/blocks";

export function proxy(request: NextRequest) {
  const response = NextResponse.next();
  const cookie = draftCookie(request);          // only set on the request Studio opens; expiring when leaving preview
  if (cookie) response.headers.append("Set-Cookie", cookie);
  return response;
}
```

## 5. Match the URL to a page

`openPage` lists pages and redirects and matches the pathname. Without streaming, one call would return the page ready to render, since the built-in `page` block resolves `seo` and every block in `sections`:

```ts
const [page] = await c.resolve<ResolvedPage<ReactNode>>(match.entry);   // page.seo, page.sections
```

This guide resolves each block separately instead, starting them all without waiting for any, so every block streams into its own Suspense boundary as soon as it's ready. Listing is cheap: the CMS holds the content in memory. Block keys include the pathname, so React mounts fresh Suspense boundaries when you navigate.

`generateMetadata` and the page component both need the page. Wrap the lookup in React's `cache` so they share one client, one match, and the same block promises.

```ts title="src/open-page.server.ts"
import "server-only";
import { cache, type ReactNode } from "react";
import { notFound, permanentRedirect, redirect } from "next/navigation";
import { matchRoute, type Redirect } from "@decocms/blocks";
import { client } from "./client.server";
import type { SEO, StoredPage } from "./model";

export const openPage = cache(async (pathname: string) => {
  const c = await client();
  const [pages, pagesError] = await c.list<StoredPage>("page");
  if (pagesError) throw pagesError;
  const [redirects, redirectsError] = await c.list<Redirect>("redirect");
  if (redirectsError) throw redirectsError;

  const match = matchRoute(pathname, { routes: pages, redirects });
  if (match.kind === "not-found") notFound();
  if (match.kind === "redirect") {
    if (match.status === 301) permanentRedirect(match.location);
    redirect(match.location);
  }

  const page = match.entry;
  return {
    blocks: page.sections.map((block, index) => ({
      key: `${pathname}:${index}`,
      result: c.resolve<ReactNode>(block),
    })),
    seo: c.resolve<SEO>(page.seo),
  };
});

export const pathnameFor = (segments: string[] = []) =>
  "/" + segments.map(encodeURIComponent).join("/");
```

## 6. Render the catch-all route

Each block is a promise of a `Result`, `[value, error]`. `BlockSlot` awaits it inside its own Suspense boundary and shows a fallback if that one block failed.

```tsx title="src/app/[[...path]]/page.tsx"
import { Suspense, type ReactNode } from "react";
import type { Metadata } from "next";
import type { Result } from "@decocms/blocks";
import { openPage, pathnameFor } from "../../open-page.server";

type Props = { params: Promise<{ path?: string[] }> };

export async function generateMetadata({ params }: Props): Promise<Metadata> {
  const page = await openPage(pathnameFor((await params).path));
  const [seo, error] = await page.seo;
  if (error) throw error;
  return { title: seo.title, description: seo.description };
}

async function BlockSlot({ result }: { result: Promise<Result<ReactNode>> }) {
  const [node, error] = await result;
  if (error) {
    console.error(error);
    return <p role="status">This content is temporarily unavailable.</p>;
  }
  return node;
}

export default async function Page({ params }: Props) {
  const page = await openPage(pathnameFor((await params).path));
  return (
    <main>
      {page.blocks.map((block) => (
        <Suspense key={block.key} fallback={<p>Loading…</p>}>
          <BlockSlot result={block.result} />
        </Suspense>
      ))}
    </main>
  );
}
```

## 7. List another content type

Add `src/post.ts` from [Your own routable types](/next/content-types#your-own-routable-types), change the `Content` export in `src/blocks.tsx` to `{ page: StoredPage; post: Post }`, and save an entry such as `.deco/blocks/HelloWorld.json` (a new file, so run `deco content` again unless `--watch` is running). Then route posts in `openPage`; without this, every post link is a 404. List posts next to pages, and return the post as is when it wins, since a post is data with nothing to resolve:

```ts title="src/open-page.server.ts (changes)"
import type { Result } from "@decocms/blocks";
import type { Post } from "./post";

  // inside openPage, after listing pages and redirects:
  const [posts, postsError] = await c.list<Post>("post");
  if (postsError) throw postsError;

  const match = matchRoute(pathname, { routes: [...pages, ...posts], redirects });
  // … not-found and redirect handling as before …

  if (match.entry.__resolveType === "post") {
    const post = match.entry as Post;
    const seo: Result<SEO> = [{ title: post.name, description: "" }, null];
    return { post, blocks: [], seo: Promise.resolve(seo) };
  }
  const page = match.entry as StoredPage;
  return { post: null, blocks: …, seo: … };  // blocks and seo exactly as before
```

In `Page`, render the post when `page.post` is set (for example `<article><h1>{page.post.name}</h1>…</article>`), and the page's blocks otherwise. `generateMetadata` keeps working unchanged.

A blog index needs no page entry. List the `post` type; each entry carries its own `path`:

```tsx title="src/app/blog/page.tsx"
import Link from "next/link";
import { client } from "../../client.server";
import type { Post } from "../../post";

export default async function BlogIndex() {
  const c = await client();
  const [posts, error] = await c.list<Post>("post", { sort: (a, b) => b.date.localeCompare(a.date) });
  if (error) throw error;
  return (
    <ul>
      {posts.map((post) => (
        <li key={post.path}><Link href={post.path}>{post.name}</Link></li>
      ))}
    </ul>
  );
}
```

## How it works

- **Preview is a different client.** `client()` is `pointer ? cms.forDraft(pointer) : cms.forRelease()`, and the pointer only exists while the cookie does. Nothing else in the guide knows about preview.
- **`openPage` takes a pathname.** React's `cache` compares arguments by identity, so pass a primitive. If content depends on query parameters, include a normalized search string in the argument. A block that needs headers or cookies reads them with `next/headers`, like any other server code.
- **Metadata waits only for SEO.** Next can stream metadata separately. A metadata error after streaming starts can't change headers that were already sent.
- **Redirect status codes.** Next's navigation helpers send 308 and 307. For an exact 301 or 302, match redirects in `proxy.ts` with `matchRoute` and return `NextResponse.redirect(url, match.status)`. Proxy makes its own client, so if a new release lands between the two, the redirect check and the page can briefly see different versions of the content.

These files use the default App Router configuration. [Cache Components](https://nextjs.org/docs/app/api-reference/config/next-config-js/cacheComponents) adds caching and Suspense requirements of its own. See the Next.js docs on [metadata](https://nextjs.org/docs/app/api-reference/functions/generate-metadata) and [proxy](https://nextjs.org/docs/app/api-reference/file-conventions/proxy).
