# Analytics

Marketing wants to know which landing page the Black Friday banner sends people to, without a cookie banner or a third-party tag manager.

Deco CMS includes small, open-source web analytics compatible with [One Dollar Stats](https://onedollarstats.com). It counts page views without cookies, and it's a [built-in block](/next/built-in-blocks), `analytics`, so you add it like any other block and editors can change it in [Studio](/next/studio). This page shows how to add it, where page views go, how to send your own events and how to turn it off.

Analytics has nothing to do with [telemetry](/next/telemetry): telemetry is errors, metrics and traces from your servers, configured in code, while analytics is page views from the browser, configured in this block.

## Add analytics to your site

### 1. Save an `analytics` block

Save a block whose type is the built-in `analytics`, with the collector page views go to:

```json title=".deco/blocks/Analytics.json"
{ "__resolveType": "analytics", "collector": "https://stats.example.com/events" }
```

Like any [saved block](/next/saved-blocks), it's a JSON file in your repository, and Studio shows it as a form.

### 2. Render it

The `analytics` block returns the tracking script as JSX, so you render it like any other block. Either put it in your root layout, so every page gets it:

```tsx title="app/layout.tsx"
import { cms } from "../cms";

export default async function RootLayout({ children }: { children: React.ReactNode }) {
  const [analytics] = await cms.forRelease().resolve("Analytics");   // a <script> tag, or null when it's off

  return (
    <html lang="en">
      <body>
        {children}
        {analytics}
      </body>
    </html>
  );
}
```

Or add `"Analytics"` to a page's `sections`, so it runs on that page only. Either way, in the browser, the script sends a page view on every navigation: the path without its query string, the referrer and the hostname.

**With [TanStack Start descriptors](/next/tanstack-start-descriptors).** There, blocks return descriptors instead of JSX, so declare `analytics` in your block map to return one too, and render it with `AnalyticsScript`, the component the built-in block uses:

```tsx
// .deco/index.ts: replaces the built-in, same props
analytics: (input: Analytics): BlockDescriptor => ({ component: "analytics", props: input }),

// src/routes/$.tsx: one more case in View
case "analytics":
  return <AnalyticsScript {...block.props} />;
```

`Analytics` (the props type) comes from `@decocms/blocks` and `AnalyticsScript` from `@decocms/blocks/analytics`. Saved blocks and page `sections` stay the same.

## Props

| Prop | Default | What it does |
|---|---|---|
| `collector` | none | The endpoint page views go to: One Dollar Stats' collector or any endpoint that accepts its format. |
| `site` | none | Your site's ID in the hosted Deco CMS, which sends page views to the hosted collector (see below). `collector` wins when both are set. |
| `enabled` | `true` | Renders nothing when `false`. |

Without `collector` or `site`, the block renders nothing, so nothing is sent. The exact type is in the [API reference](/next/api-reference#types).

<Hosted to="/next/hosted" label="The hosted Deco CMS">**Analytics with nothing to run.** Set `site` instead of `collector`, `{ "__resolveType": "analytics", "site": "my-store" }`, and the hosted Deco CMS collects your page views and shows them for your site. The site ID isn't a secret, so it's safe in content.</Hosted>

## Send your own events

Call `track` from `@decocms/blocks/analytics`, with an event name and optional properties:

```tsx
import { track } from "@decocms/blocks/analytics";

<button onClick={() => { addToCart(sku); track("add_to_cart", { sku }); }}>Add to cart</button>
```

`track` sends through the script the `analytics` block renders. On a page without it, `track` does nothing.

## Turn it off

Set `enabled` to `false`, in Studio or by hand:

```json title=".deco/blocks/Analytics.json"
{ "__resolveType": "analytics", "collector": "https://stats.example.com/events", "enabled": false }
```

It's a content edit, so it ships like any other, and switching it back on is the same one-field commit. Because it's a block, you can also wrap it in [variants](/next/matchers-and-variants), to run it only during a campaign, for example.

## One Dollar Stats

Page views use the wire format of the One Dollar Stats tracker, so the two halves mix and match:

- point `collector` at One Dollar Stats' own collector, or
- use their tracker script on your site and send to a collector that accepts the format.

The format isn't versioned, so Deco CMS tests against a pinned tracker version; the details are [under the hood](/next/telemetry-internals#analytics-events).

## Privacy

- No cookies, nothing stored in the browser and no fingerprinting: a page view is a path, a referrer and a hostname.
- Query strings are dropped, so search terms and tracking parameters stay out of your data. Keep personal data out of `track` properties.
