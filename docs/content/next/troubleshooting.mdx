# Troubleshooting

Most problems come down to three facts: which revision this server is serving, which entry was asked for, and which block type it names. Until the client exposes its revision (see the [Roadmap](/roadmap#roadmap-api--add-a-revision-handle)), log `content.revision` from the content module you pass to `createCMS`: that's the revision this build serves. `.deco/blocks.gen.ts` holds the same value, so you can compare it with a fresh `deco content` run on the commit you expect. To see an entry with references expanded but no function run, call `client.resolve(target, { run: false })`. To see it exactly as stored, open `.deco/blocks/<name>.json`.

| Symptom | What to check |
|---|---|
| `UNKNOWN_BLOCK` | A `__resolveType` names something that is in neither the block map nor the saved blocks. [Built-in blocks](/next/blocks#built-in-blocks) never cause it. Compare `__resolveType` with your block map's keys, including case. A type declared only in `Content`, such as `post`, has no function, so read its entries with `list` or `{ run: false }` rather than resolving them. Add an [alias](/next/renames-and-migrations) for renamed types. If the function does a dynamic `import()`, confirm the imported module has a default export. |
| `NOT_FOUND` | A string target is always a saved block's name, never a block type. Confirm the entry exists in the served revision, that `createCMS`'s `content` is the content you expect, and that `deco content` ran after the file was added (see [Configuring content](/next/api-reference#configuring-content)). To run a type directly, pass an inline block: `client.resolve({ __resolveType: "seo", … })`. |
| `CYCLE` | Follow the references in `error.path` and remove the one that leads back to an entry already being expanded (see [The rule in full](/next/how-resolution-works#the-rule-in-full)). |
| My saved block is ignored | A block type probably has the same name, and the function wins. Run `npx @decocms/blocks schema`, which reports the collision, and rename the entry. |
| Blocks come back as JSON instead of running | You called `client.list` without `{ run: true }` (it returns saved blocks by default), or you passed `{ run: false }` to `resolve`. To run listed entries, pass `run: true`, or resolve each listed entry with `client.resolve(entry)` (a page comes back fully resolved). |
| A function runs more than once per request | A client runs each block once and reuses the result, but only within that client and for that block map object. Make one client per request, not per component, and create the block map at module level, not inside your handler. |
| Wrong fields in the editor | Regenerate the schema from the right `blocks.ts`. Check the first parameter's type and its property JSDoc (see [Schema](/next/schema)). |
| Serialization error when sending a block's result to the browser | JSON can't carry functions or React elements. Return plain data (descriptors, see [Rendering](/next/rendering)), or use an integration that renders on the server, like [TanStack RSC](/next/tanstack-start-rsc) or [Next.js](/next/nextjs). |
| Hydration mismatch (React's browser render doesn't match the server's HTML) | Look for time-dependent or random rendering, and for request context the server and browser see differently. If the browser fetches data after the page loads, it may get a newer revision; render data that must match the HTML in the same response. |
| Content changes mid-response | Use one client for the whole response; a client never changes revision. If you pass a custom `content` object, check that it never returns different content under an existing revision. |
| Old content after a deploy | Compare the revision your server logs (see above) with the one in `.deco/blocks.gen.ts` after running `npx @decocms/blocks content` on your latest commit. If they differ, the build didn't rerun `deco content`: check that `prebuild` runs `deco schema && deco content` and that the build checked out the commit you expect. See [Releases and deployment](/next/releases-and-deployment). |
| `UNKNOWN_BLOCK` right after a content change | The content uses a block type its code doesn't have, usually because it was committed before the code that defines the type, or the code was rolled back to a version without it. Ship the code in the same change, or revert the content commit. See [Change types safely](/next/schema#change-types-safely). |
| A new content file isn't found in development | Run `npx @decocms/blocks content`, or keep `npx @decocms/blocks content --watch` running beside your dev server. Only adding or removing a file needs it; edits to an existing file hot-reload. |
| `deco: command not found` | In a terminal, run `npx @decocms/blocks <command>`. The short name `deco` works inside `package.json` scripts once `@decocms/blocks` is installed; if a script can't find it, run `npm install` (see [CLI](/next/cli)). |
| `Cannot find package 'typescript'` when running a `deco` command | The CLI uses your project's TypeScript. npm and Bun install it with `@decocms/blocks`; with another package manager, run `npm install -D typescript` (or its equivalent). |
| Warning about an instance with different options | `createCMS` ran twice with the same content but different options. The first instance is kept. Create the CMS once, at module scope (see [One instance per process](/next/api-reference#one-instance-per-process)). |
| Studio can't reach `deco serve` | Check that the server is still running and that you opened the link from this run: a restart prints a new token, and Studio asks you to reconnect. Allow the browser's prompt to let Studio reach your machine (Local Network Access). If you use another browser origin than Studio's, pass it with `--allow-origin`. See [Studio and the content protocol](/next/content-protocol#edit-your-local-checkout). |
| A form field in Studio is a text box instead of a picker | Studio never runs your code, so options that would come from a function aren't available in this version. Give the field a string-literal union, an enum or an `@options` list, and run `npx @decocms/blocks schema` (see [Choose widgets with JSDoc](/next/schema#choose-widgets-with-jsdoc)). |

Problems specific to the hosted Deco CMS, such as a release that hasn't reached a server or telemetry that doesn't arrive, are in [Publishing without a deploy](/next/hosted-publishing#troubleshooting) and [Telemetry](/next/hosted-telemetry#troubleshooting).
