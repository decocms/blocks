# Hosted telemetry

You want upstream latency and error rates for your site, but you don't want to run a collector or a dashboard. The hosted Deco CMS runs one for you.

[Telemetry](/next/telemetry) is open source and can go to any OpenTelemetry collector. This page shows how to send it to the hosted Deco CMS instead, and what you get there. Page views are [analytics](/next/analytics), which is separate: the `analytics` block sends to the hosted collector by default.

## Turn it on

Pass your site's ID and token as the `telemetry` option of [`createCMS`](/next/api-reference#createcms-config):

```ts title="cms.ts"
const { DECO_SITE: site, DECO_SITE_TOKEN: token } = process.env;

export const cms = createCMS({
  blocks,
  content,
  site,                                               // loads releases and drafts
  token,
  telemetry: site && token ? { site, token } : false, // telemetry is separate: site/token above only load releases
});
```

They're the same values that [connect your site](/next/hosted#connect-your-site) for releases and drafts, but telemetry is passed explicitly: the top-level `site` and `token` alone never send it. The `site && token` check keeps telemetry off where the variables aren't set, such as on your machine.

## What you get

The hosted Deco CMS collects and shows, for your site, the [measurements](/next/telemetry#whats-sent) your site sends: upstream latency and error rates per provider, inbound requests, cache hits and misses, sampled error logs, and traces when you turn them on.

## Settings

What's sent and how often is the same as with any collector: the [`Telemetry` saved block](/next/telemetry#telemetry-settings-are-content) holds the switches and sample rates, and [`limits`](/next/telemetry#sampling) in code cap them.
