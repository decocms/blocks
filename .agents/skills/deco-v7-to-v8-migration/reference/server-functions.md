# `/deco/invoke` → server functions

From the site migrations; the sites and what the commit hashes refer to are listed in `SKILL.md` ("Gotchas by subject").

v8 has no invoke endpoint. Every call the browser made through `/deco/invoke` becomes a TanStack Start server function (`createServerFn`) or a Next server action, taking the request and response headers explicitly (`89895c3`). Validate inputs with zod; reject protocol-relative hrefs. Loaders that 404'd through invoke and fell back to placeholders now return real state: check those flows.

- **One server function per key, imported by the call site: the script writes them.** `src/server/invoke.functions.ts` (TanStack; a loader is a GET with `markPrivate()`, an action a POST) or `src/server/invoke.actions.ts` (Next.js, `"use server"`), named after the key (`site/loaders/gateway/wishlist/add-item` → `$siteLoadersGatewayWishlistAddItem`), each calling its handler module with the props (`{}` for none, as v7 sent) and the request. Each call becomes `invoke.a.b(props)` → `$aB({ data: props })` (Next.js: `$aB(props)`), across lines, bracket keys (`["can-spin"]`), flat keys (`invoke["vtex/loaders/x.ts"]`), `invoke(key, props)` and `Runtime.invoke` included; v7's proxy module (`src/runtime.ts`) is deleted once nothing imports it. An app's key vendors the app's module when it default-exports the handler. A computed key is reported and left. Then type each function (input and result are `any`, as v7's invoke was) and forward the cookies a handler sets. Never a `runInvoke(key)` lookup over the commerce-loader map: that is v7's endpoint again.
- **What has no server function is a stub.** `unportedInvoke(key, props)` from `src/migration-stubs.ts` rejects: `ctx.invoke` in a loader (call the handler module directly with `(props, req)`), and a key nothing answers. `appState(name)` throws where a loader read an app's state off `ctx` (`ctx.vtex`, `ctx.getAppState("x")`); pass the setting in, or call the client in `src/clients/`. Only a v7 loader's `ctx` (`(props, req, ctx)`) is rewritten, never another third argument such as React Query's `onError` context.
- **v7's invoke passed no app context.** It called `handler(body, request)`. A site loader that reads its third argument (account, secrets) worked when a page ran it (the block map passed them) and threw through invoke. Give its server function the context the block map passes.
- **Keys v7 had no handler for** failed with "handler not found". The script keeps them failing at the call site (`unportedInvoke`, reported as such), not as stubs in a rebuilt `invoke` tree: list them as follow-ups.
- **Check the client bundle.** TanStack Start's compiler replaces each handler with an RPC stub and drops its imports; grep `dist/client` JavaScript (not source maps) for secret env names and `node:async_hooks` after the build.
- v7's generated `invoke.gen.ts` (cart and session actions) is site code now: export each action as its own server function and delete the ones nothing calls.
