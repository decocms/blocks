# Next.js App Router

From the site migrations; the sites and what the commit hashes refer to are listed in `SKILL.md` ("Gotchas by subject").

- **`transpilePackages: ['@decocms/blocks']`** only while the installed package's `exports` point at `.ts` source (see `manual-steps.md`, step 1); `8.1.0` ships `dist/` and needs none. A linked local checkout ships `dist/` and hides the difference; so does every parity run made against it.
- **Drafts on Pages Router SSG pages** (no proxy available, as on FastStore; `@decocms/nextjs` is for the App Router): Next 16's compiled pages runtimes inline `tryGetPreviewData`, so a `require.cache` patch never runs. See `faststore.md`.
- **Drafts come from `@decocms/nextjs`.** Don't hand-write the draft proxy, the draft route or the Studio bridge. In `proxy.ts`: 404 direct hits on the internal route (`isDraftRoutePath`), `decideDraft(proxyCms, request)`, then `decideVisitor(request, draft)` and `decideAssignments(proxyCms, draft, visitor)`, then `rewriteToDraftRoute(request, draft, visitor, assignments)` or `NextResponse.next({ request: { headers: assignmentsRequestHeaders(visitorRequestHeaders(draftRequestHeaders(request, draft), visitor), assignments) } })`, and `applyVisitor(applyDraft(response, draft), visitor)` for the cookies and the no-store/noindex headers (`@decocms/nextjs/proxy`). The visitor (the `deco_segment` cookie, v7's format plus an id) is what the saved `experiments` block decides A/B tests for; the proxy decides each test and campaign once (`decideAssignments`, forwarded with `assignmentsRequestHeaders`), `bindDraft` binds what it decided and `contentClient` builds `cms.client({ version, experiments, campaigns })` (`draftProxy` does all of it). On the dynamic `src/app/%5Fdraft/[[...path]]` route and in a layout that reads content: `bindDraft(cms, { searchParams })` and `contentClient(cms)` (`@decocms/nextjs/server`), with `<DraftPreviewIndicator />` on the page. A cached page can't read a request, which is why drafted requests go to that dynamic route; published CMS pages are ISR with `export const revalidate = 600` (Next renders a stored page again in the background on the first request after it is 10 minutes old, so a cached page is about that stale, which is accepted), never `force-static`, on the assignments route where the proxy decides the tests and campaigns and the page renders that (`await assignedClient(cms, segment)`). The package's README has the files in full.
- **Same CMS options in the proxy and the pages.** Keep `createCMS`'s options in one module both handles import (`cmsConfig`, with `site`): the proxy decides on the hosts Studio writes into the release metadata, and `bindDraft` checks again against the same ones.
- **Keep the block map out of the proxy.** The proxy only touches the CMS for a request with `?__draft=` or the draft cookie, but it is bundled whole. Give it its own `createCMS` handle with `blocks: {}` and the same options as the app's (one shared options module, since a second call with other options keeps the first): the draft check reads only the `CMS` settings block, so the block map, its section loaders and what they import (a GraphQL engine) leave the proxy bundle. Measured on one store: 2.2 MB to 1.5 MB, traced files 3,245 to 364. The content module still lands there.
- **`next start -H 127.0.0.1`** makes Next treat the draft rewrite as an external URL, and the request comes back through the proxy. Bind the default host in local checks; production hostnames aren't affected.
- **`Vary: Cookie`** doesn't arrive on a draft page: Next sets `Vary` itself. `Cache-Control: no-store, private` and noindex do.
- **next.config**: `withDeco(config)` from `@decocms/nextjs/config` (plain CommonJS) puts v7's draft header rules first and adds Studio's origins to `allowedDevOrigins`. Delete hand-written copies of those rules.
- **Images**: `createDecoImageLoader(imageUrl, { fallback: nextImageOptimizer })` from `@decocms/nextjs/image-loader` as `images.loaderFile`, over `createImageUrl` from `@decocms/blocks/image` with the platform's helpers first (`@decocms/apps-vtex/image`; see `framework-code.md`). A Server Component can't pass the URL function to a client component, so use the loader file, not a wrapper component.
- **A pointer that doesn't parse.** `cms.draftPointer` ignores a `?__draft=`/cookie value that doesn't parse (it returns `null`, so `?__draft=junk` gets the release). On a `@decocms/blocks` release without that fix it returned the raw value and `cms.forDraft` failed with `LOADER_FAILED`, so `?__draft=junk` on a preview host answered 500: there, treat `parseDraftPointer(pointer) === null` as no draft, in the proxy and the page.
- **Views wrapped in `next/dynamic`.** The script types each section from its view (`PropsOf<view>`). A lazy view that re-exports a `next/dynamic` wrapper loses its props type, and its form collapses. Type those sections from the component module (`section<import("…").Props>(…)`) and diff the forms against v7's.
- **`list('page')` order.** It sorts by block name; v7 listed saved pages in file order. Output that lists pages in order (a sitemap) has to keep v7's order explicitly.
- **List pages once per revision.** `list('page')` expands every page's saved-block references; on a site with hundreds of pages that is tens of milliseconds of CPU. Keep the routable list per revision (a revision never changes, a draft has its own) and hand the same array to `matchRoute` so it reuses its lookup. Health and readiness probes go through the same cache, never a fresh `list`.
- **Head meta order.** If v7 emitted `theme-color`/`color-scheme` after the root layout's metas on some routes, that was a race with Next's viewport resolution. To keep the order deterministic, render those tags from the segment layout (React hoists in tree order) rather than approving a reorder. The race can go the other way: where v7 had the viewport tags *before* the root layout's metas and v8's faster shell now wins, a segment layout can't move them earlier. Look for a deterministic fix (the tags rendered ahead of the root layout's metas on every route, checked against every route's head), and keep the reorder pending, with that reasoning, if none holds.
- **Jest** is CJS-only: transform `@decocms/blocks` (ESM) with ts-jest and keep it out of `transformIgnorePatterns`. When mocking a site module in a test, spread `jest.requireActual` so sibling exports other code imports stay real.
