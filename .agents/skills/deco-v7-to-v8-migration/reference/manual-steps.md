# Manual steps (what the report leaves)

The full text behind `SKILL.md` ("Manual steps"). Work through the report top to bottom; these are the steps it groups its "Left to do" lines under.

1. **Dependencies.** Depend on `@decocms/blocks@^8.3`, the v8 binding at the same version (`@decocms/tanstack@^8.3` or `@decocms/nextjs@^8.3`; they take blocks as a peer, so one copy installs), `@decocms/compat-v7@^8.3` when the script pointed imports at it and the v8 `@decocms/apps-<platform>` client. Remove `@decocms/blocks-admin`, `@decocms/blocks-cli`, `@decocms/apps-commerce`, `@decocms/apps-website` and `@decocms/apps-blog` once nothing imports them, and drop the v7 codegen from `build`. On Next.js, check what the installed `@decocms/blocks` publishes: when its `exports` default to `dist/*.js` (`8.1.0` does), it needs no `transpilePackages` entry; a prerelease whose `exports` point at `src/*.ts` needs `@decocms/blocks` in `transpilePackages` (v7's `withDeco` wrapper used to add it), or a clean install fails `next build` with `Module parse failed: Unexpected token`.
2. **Render pages with `createCMS`, on the binding.** Follow the framework guide (`/next/tanstack-start-descriptors`, `/next/nextjs`): `createCMS` over the content, `matchRoute`, one promise per block, the view registry the script wrote (`src/views.ts`). Where the report says so, call `matchPage(href)` before resolving and `loadSections` after, and send v7's A/B cookie (`commitSegmentCookie()`, `cohortSegment` in the worker's `segment`; on Next.js `pageUrlRequestHeaders` in the proxy and `<SegmentCookie />`). Wire the binding as its README shows: on TanStack, `createDecoWorker` as the worker entry, `DecoDocument` as the root, `createDecoRouter`, `decoServerFnFetch` and `decoTanstack()`; on Next.js, the draft proxy and route, `StudioBridge`, `withDeco` and the image loader (`reference/framework-code.md`). Delete the v7 setup files, admin routes and `/deco/*` handlers. Delete the v7 CI jobs too: a `.github/workflows/regen-blocks.yml` (or any job that runs `generate:blocks` or calls the shared `regen-blocks` workflow) regenerated `blocks.gen.json` on every content push to `main`. v8 has no such file and the script it calls is gone, so once merged every publish starts a job that fails or does nothing useful.
3. **Replace v7's framework code with the binding, and move the rest into the site** (`reference/framework-code.md`): the worker, drafts, the Studio bridge, the badge and the image components come from the binding, a platform's image URLs from its client's `/image` (`@decocms/apps-vtex/image`, `@decocms/apps-shopify/image`); SEO/head, device detection, cookies, cart/user/wishlist flows, commerce loaders and converters are site code.
4. **Replace `/deco/invoke`** with server functions (TanStack `createServerFn`) or Next server actions/route handlers. One exported server function per loader or action the browser called, and each call site imports the one it calls: `invoke.site.loaders.spin(props)` becomes `$siteLoadersSpin({ data: props })`. Don't rebuild the `invoke.x.y` tree or a string-keyed dispatcher over the commerce-loader map (see DO NOT in `SKILL.md`); the server function calls its handler directly. Details in `reference/server-functions.md`.
5. **Fix the content `deco check` rejects**: fields no type declares, `.tsx`-named preview blocks, v7 app blocks (apps are code now), `requestToParam` blocks in string fields.
6. **Telemetry, analytics and previews**: the `telemetry` option of `createCMS` (`/next/telemetry`), with switches and rates in the `telemetry` section of `CMS.json`; `AnalyticsScript` with `const { analytics } = await cms.settings()` and `track` from `@decocms/blocks/analytics`; drafts through the binding (the TanStack worker, or `decideDraft`/`bindDraft` on Next.js), which applies v7's host allowlist: the hosts the site declares in the `CMS` block's `preview.hosts` (none when it lists none, as in v7: blocks' every-host default doesn't apply), plus `<site>.deco.site` and `<site>.deco-cx.workers.dev` from the `site` option; `previewHosts: [...]` replaces the block's list and `previewHosts: "none"` turns previews off, where v7 read `DECO_ALLOWED_PREVIEW_HOSTS`. The report's "preview hosts" line says what to pass to keep v7's hosts; list the dev server's host with its port (`localhost:5173`, `localhost:3000`) when editors preview there, and name each host you add for the product owner. The report carries GTM/GA4 IDs over. If v7 sent no CMS telemetry, pointing `telemetry` at the site's existing collector is new traffic and cost there: list it as a behaviour change.
