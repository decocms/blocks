# Extending the migrator

Paths are relative to `packages/blocks-cli/scripts/migrate/`. Every change
here needs a colocated `*.test.ts`, and — when it changes what a user sees (a
flag, a phase, a report section, a rewrite rule) — a matching update to the
`tools-migrate-script` skill in `decocms/migrations`.

## The core types (`types.ts`)

`types.ts` is authoritative; this is the shape to keep in your head.

- **`MigrationContext`** — the one object threaded through every phase.
  Inputs: `sourceDir`, `layout` (phase 0), `config` (`.deco-migrate.config.json`
  or `null`), `dryRun`, `verbose`. Analyze fills site metadata — `siteName`,
  `platform`, `vtexAccount`, `gtmId`, `importMap`, `discoveredNpmDeps`,
  `themeColors`, `fontFamily`, `googleFonts`, `tailwindConfig` — and the
  inventories: `files: FileRecord[]`, `sectionMetas`, `islandClassifications`,
  `islandWrapperTargets`, `loaderInventory`. Later phases append to the report
  accumulators: `scaffoldedFiles`, `transformedFiles`, `deletedFiles`,
  `movedFiles`, `manualReviewItems: ReviewItem[]`, `frameworkFindings`.
- **`FileRecord`** — `path`, `absPath`, `category` (`section` | `island` |
  `component` | `sdk` | `loader` | `action` | `route` | `app` | `static` |
  `config` | `generated` | `other`), `patterns: DetectedPattern[]`, `action`
  (`transform` | `delete` | `move` | `scaffold` | `manual-review`), optional
  `targetPath` (for moves), `isReExport`/`reExportTarget`, `notes`.
- **`Platform`** — `vtex` | `vnda` | `shopify` | `wake` | `linx` | `nuvemshop` |
  `magento` | `custom`, detected from `apps/site.ts` or `deno.json` imports. It
  drives commerce type imports, loader registration, the `setup.ts` template
  and API proxy configuration.
- **`ReviewItem`** — `{ file, reason, severity: "info" | "warning" | "error" }`.
  A `MANUAL:`-prefixed reason is how a detector surfaces something it will not
  auto-fix; `phase-report.ts`'s `isCssReviewItem` routes CSS ones into the
  report's CSS Migration section.
- **`TransformResult`** — `{ content, changed, notes }`.

## Adding a transform

1. Create `transforms/my-transform.ts`:

```typescript
import type { TransformResult } from "../types";

export function transformMyThing(content: string): TransformResult {
  let changed = false;
  const notes: string[] = [];
  let result = content;

  const next = result.replace(/oldPattern/g, "newPattern");
  if (next !== result) {
    changed = true;
    notes.push("Replaced oldPattern → newPattern");
    result = next;
  }

  return { content: result, changed, notes };
}
```

2. Add it to the `pipeline` array in `phase-transform.ts`. **Order matters** —
   the comment above the array records why each transform sits where it does
   (e.g. `htmx-on-events` after `jsx`, before `fresh-apis`; `ctx-compat` after
   `fresh-apis` so it sees the settled loader body). Write down your reason
   there too.

```typescript
import { transformMyThing } from "./transforms/my-transform";

const pipeline = [
  { name: "imports", fn: (c) => transformImports(c, ctx?.islandWrapperTargets) },
  { name: "jsx", fn: transformJsx },
  // …
  { name: "my-thing", fn: transformMyThing },
  { name: "tailwind", fn: transformTailwind },
];
```

3. Make it a no-op on files it does not concern (as `ctx-compat` is on files
   without a `loader` export) — the pipeline runs on every source file.

A Tailwind/DaisyUI rename goes into `transforms/tailwind-renames.ts`, never a
new table (see "Rules that are easy to break" in `SKILL.md`).

## Adding a template

1. Create `templates/my-file.ts`:

```typescript
import type { MigrationContext } from "../types";

export function generateMyFile(ctx: MigrationContext): string {
  return `// Generated by migration script
export const siteName = "${ctx.siteName}";
`;
}
```

2. Call it from `phase-scaffold.ts` with the local `writeFile` helper (it
   honours `--dry-run` and records the file in `ctx.scaffoldedFiles`):

```typescript
import { generateMyFile } from "./templates/my-file";
writeFile(ctx, "src/my-file.ts", generateMyFile(ctx));
```

3. If the file must exist on every run, add it to `REQUIRED_FILES` in
   `phase-verify.ts`.

## Adding a smoke check

Append to the exported `checks` array in `phase-verify.ts`. `severity: "error"`
fails the run (exit 2); `"warning"` lands in manual review.

```typescript
{
  name: "No foo imports in src/",
  severity: "error", // or "warning"
  fn: (ctx) => {
    const bad = findFilesWithPattern(path.join(ctx.sourceDir, "src"), /from ["']foo["']/);
    if (bad.length > 0) console.log(`    Still has foo imports: ${bad.join(", ")}`);
    return bad.length === 0;
  },
},
```

## Adding an analyzer

Put it in `analyzers/`, call it from `phase-analyze.ts`, and store the result on
`MigrationContext` (add the field in `types.ts`). Anything read from a file
cleanup deletes must be read here — see `analyzers/tailwind-config.ts`. Prefer
static extraction (ts-morph) and turn what you cannot read confidently into a
`ReviewItem` instead of guessing.

## Adding a post-cleanup rule

Rules live in `post-cleanup/rules.ts` (each with an `id`), run by
`post-cleanup/runner.ts`, tested in `post-cleanup/runner.test.ts`. Mark a rule
auto-fixable only if `--fix` is safe with no human in the loop; the migrator's
phase 9 always runs it read-only.

## Debugging at the code level

| Symptom | Where to look |
|---|---|
| Aborts at phase 0/1 on a real Deco site | `source-layout.ts` (layout detection) and the categorisation in `phase-analyze.ts` — the source should have `sections/` or `src/sections/` and `deno.json` or `import_map.json` |
| Some files are never transformed | `phase-analyze.ts` categorisation — the file sits outside a recognised directory; add the glob |
| z-index stacking still broken | `transforms/tailwind.ts` only fixes `-z-{n}` on images (overlay-div pattern); a new pattern is a new rule there |
| Opacity modifier not consolidated | By design for non-adjacent `bg-{color}` + `bg-opacity-{n}` — they are flagged, not merged |
| Bootstrap fails at generate-blocks | Missing or malformed `.deco/blocks/*.json` in the source — not a migrator bug unless the source is valid |
| `package.json` pins `"latest"` | The npm registry fetch in `templates/package-json.ts` failed; it falls back to `"latest"` |
| A typecheck regression only shows in phase 8 | A transform produced invalid TS that `phase-verify` cannot see (e.g. #105, `.ts` extensions) — add a verify check or fix the transform |
